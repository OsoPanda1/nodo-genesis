## 1. Fundamentación ontológica

C.R.O.W.N. no es una especificación convencional de software: es un **sistema operativo
constitucional de web nativa (ZT-DCOS)** para garantizar soberanía de datos, antifragilidad y
ejecución ética en sistemas descentralizados. Bajo la dirección del Nodo Cero en Mineral del
Monte, el ecosistema **TAMV Online** opera con una separación estricta entre el plano normativo
(Constitución C.R.O.W.N.) y el plano ejecutable (Runtime YUN).

| Componente | Dominio funcional | Tecnología / protocolo nativo |
|---|---|---|
| **C.R.O.W.N. Kernel** | Constitución y gobernanza ontológica | Smart Contracts Semánticos / Manifiesto RFC-0001 |
| **ISA API** | Núcleo cognitivo y razonamiento estructurado | Prompt Guard (9 categorías) + Intention Parser |
| **Mexa API** | Criptografía post-cuántica y seguridad | Algoritmos Dilithium-5 / Firmas MSR inmutables |
| **YUN Fabric** | Orquestación y bus de eventos distribuidos | YunEvent Bus / Protocolo de Sostenibilidad SCAO |

## 2. Pipelines de procesamiento cognitivo (ISA API)

El flujo de ejecución en `/api/isabella/chat` y `/api/isabella/isa/reason` procesa cada
interacción mediante un pipeline estricto de saneamiento, análisis de intención, razonamiento
formal y auditoría criptográfica:

```
[Entrada de Usuario]
       │
       ▼
┌──────────────────────────────┐
│ Prompt Guard (9 Categorías)   ├─► [Rechazo / Alerta de Seguridad]
└──────────────┬───────────────┘
               │ (Sanitizado)
               ▼
┌──────────────────────────────┐
│ Intention Parser (8 Dominios)│
└──────────────┬───────────────┘
               │ (Clasificado)
               ▼
┌──────────────────────────────┐
│ Structured Reasoning Engine  ├─► Trazabilidad (Answer, Sources, Trace)
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│ Mexa API (Firma Criptográfica)│ ──► Registro en YUN Ledger / Zenodo DOI
└──────────────────────────────┘
```

### Endpoints nativos (ISA API)

- `/api/isabella` · `/api/isabella/chat` (Público) — pipeline completo con sanitización,
  interpretación, orquestación, evaluación y registro inmutable.
- `/api/isabella/isa/reason` (Público) — motor de razonamiento estructurado con trazabilidad
  (`Answer`, `Sources`, `Trace`).
- `/api/isabella/crypto/sign` (Operador) — emisión de firmas criptográficas MSR.
- `/api/isabella/crypto/verify` (Público) — verificación de procedencia e integridad de artefactos.

## 3. Métodos de Machine Learning y filtros de seguridad nativos

- **Prompt Guard Multi-Capa** (`lib/isabella/prompt-guard.ts`): expresiones regulares ponderadas
  y clasificación de riesgo (`none → critical`) sobre **9 categorías de amenaza**, incluyendo
  jailbreaks y **triple bloqueo contra sexualización no autorizada**.
- **Intention Parser Vectorial** (`lib/isabella/intention-parser.ts`): clasifica la intención en
  **8 dominios canónicos** (submission, library, constitution, governance, ecosystem, education,
  skills, ethics) con **14 patrones regex** ponderados y confianza calculada.
- **Structured Reasoning Engine**: vincula respuestas con fuentes verificables y genera un
  identificador de traza (`trace_id`) auditable.
- **PRA Score Engine** (`lib/isabella/pra.ts`): Algoritmo de Olvido Activo y relevancia de
  memoria bajo los principios FAIR & POSI.

## 4. Reglamentos y modelos de licenciamiento híbrido

- **LICENSE-KORIMA** — inspirada en el principio de ayuda mutua rarámuri: obligación moral y
  técnica de reinyectar valor (código, mantenimiento o datos validados) al ecosistema.
- **LICENSE-EOL** (Dead Man's Switch Digital) — mecanismo automatizado de respaldo y replicación
  inmutable en redes distribuidas (IPFS/Arweave) ante el cese operativo de un nodo físico.
- **Split de Soberanía 75/25** — el creador retiene el **75%** del valor de su obra; el restante
  25% se distribuye entre el **Fondo Fénix (20%)**, **Infraestructura (30%)** y **Utilidad de la
  DAO (50%)**.

## 5. Configuración de base de datos y gobernanza YUN

La arquitectura de datos de YUN separa los dominios para garantizar una única fuente de verdad
por entidad, bajo el principio *"Always by your side"*.

```python
class YunEvent(BaseModel):
    event_type: str
    domain: str
    federation_id: str
    entity_id: str
    trace_id: str
    timestamp: str
    severity: str
    payload: dict

def publish_yun_event(event: YunEvent):
    print(f"[YUN FABRIC] Evento registrado [{event.domain}] -> Trace: {event.trace_id}")
```

En el runtime TypeScript, el equivalente es `lib/isabella/events.ts` (`emitYunEvent`), usado
por Isabella y por los módulos del Hub (incluida la gamificación **Zombies RDM Invasion**, que
publica eventos de dominio `gameplay`).
